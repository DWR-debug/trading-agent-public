# Q133–Q170 PIT Readiness R1 — 2026-10-03

## Purpose

This wave is a downstream research gate for the **21 candidates that were classified as source-feasible** by the persisted Q133–Q170 discovery receipt.

The persisted source-feasibility receipt contains **25 passed source probes across 38 candidates**. The number 25 is therefore a source-endpoint count, not a count of performance candidates. Twenty-one candidates are currently source-feasible; the other 17 remain blocked or design-only.

This wave does **not** evaluate returns and does not rank candidates. Its purpose is to determine whether a source-feasible mechanism can be represented as a reproducible historical information set without look-ahead.

## Scientific sequence

For each source-feasible candidate:

1. re-use the immutable source-feasibility receipt and its fingerprint;
2. identify the exact information boundary required by the candidate's frozen design;
3. classify clock, revision/version, identity/mapping and historical-archive requirements;
4. run only bounded public sample probes where a low-cost deterministic sample exists;
5. apply future-row mutation checks to the compiler boundary;
6. classify unresolved candidate-specific PIT work explicitly.

A candidate is **not PIT-valid** merely because its source endpoint is reachable or a generic historical sample exists.

## Conservative result classes

- `PIT_SAMPLE_STRUCTURAL_SUPPORT`: a bounded public sample demonstrates the required timestamp/version field or historical addressing pattern.
- `SOURCE_DATA_SAMPLE_REACHABLE`: a public data sample is reachable but does not establish the candidate-specific information boundary.
- `PIT_CONTRACT_DEFINED_PENDING_ARCHIVE`: timing/revision/identity requirements are explicit, but historical candidate-specific reconstruction is not complete.
- `PIT_CONTRACT_UNRESOLVED`: one or more candidate-specific semantics remain materially unspecified.
- `INFRA_ACCESS_BLOCKED`: the public endpoint could not be reached or parsed. This is treated as an infrastructure/access result, never as evidence that the historical dataset is absent.
- `BLOCKED_SOURCE_FEASIBILITY`: retained for completeness when a candidate is not source-feasible.

No result class in this wave authorizes performance.

## Required downstream gates

PIT readiness still requires:

- candidate-specific source/entity mapping;
- exact publication/acceptance/dissemination boundary;
- revision/amendment/version semantics;
- historical coverage sufficient for the intended validation universe;
- immutable input preservation;
- independent PIT reproduction;
- only then, a fresh preregistration and separate performance authorization.

Holdout selection, candidate ranking, parameter search, threshold search, horizon search, asset search, promotion and live execution remain disabled.
